# Practice sessions and routines

Sign in and select Practice. Sessions and routines are private. Choose an instrument and optional song, private chord, chord symbol, technique/focus and notes. Start with a blank timer target for count-up or a whole-minute target. One unfinished session is allowed per account. Start, pause, resume, end and explicitly save. Refresh, navigation and browser sleep do not lose elapsed server time. They also do not infer whether you were actually practicing: pause for breaks and correct accidental idle time before saving. A target ends exactly at its active-time deadline on the next server read, never automatically saves, and never counts sleep beyond the target.

History contains saved sessions only, newest first, paginated 50 at a time with page-local search. Edit metadata or explicitly correct start/active seconds. The correction form labels the device timezone; stored intervals are UTC and record the profile timezone captured at start. A time correction replaces pause segments with one continuous interval. Only 1–86400 active seconds are saveable; over four hours requires confirmation. Future or overlapping saved active intervals are rejected. Retry-safe Start and Save plus per-account transaction locking prevent duplicate time. Delete/discard physically removes the session. A minimal owner/key/hash/session reference ledger prevents a delayed Start retry recreating deleted practice; it has no notes, intervals or routine content and cascades on account deletion.

Build reusable activities with names, seconds, order, tool, tempo and optional song/chord/pattern. Routines have 1–30 activities, each 1–14400 seconds, total at most 24 hours. Reorder with keyboard-accessible up/down controls. Editing/deleting a routine does not rewrite existing session snapshots. Repair missing song/pattern targets before starting/duplicating a template. Unavailable snapshot links are displayed honestly; private chord voicings are never substituted silently. Chord drills show one selected diagram for self-directed changes, not automatic playing assessment. A blank chord defaults to C when a diagram is required.

The player follows active time automatically. Show guided tools, then explicitly start audio. Existing metronome and pattern audio engines are reused; pattern/click playback shares one clock. Pause/end/activity changes/navigation release local audio. Background audio can suspend independently of the persisted practice timer. Song/tuner links open another tab; stop any independently started tool there yourself. No microphone is opened by the Practice page. Pattern playback uses synthesized chords, not recorded guitar. No accuracy or learning assessment is inferred.

Set or pause daily/weekly targets. Suggestions of 15/90 minutes are unsaved form defaults, not goals already chosen for you. Changes append effective-dated goal versions; pausing does not delete history. Progress aggregation, calendar allocation, streaks, charts and roadmap belong to Phase 14. Proposed Monday/day-qualification/historical-timezone policies remain undecided there. No timezone policy is silently accepted by storage here. Deterministic routine recommendations (UNI-005 MAY) are not selected for Phase 13; reconsider in Phase 16.

## Architecture and operations

Pure timing rules are in `practice/domain.py`, independently tested without FastAPI/ORM. Typed request/response contracts live in schemas; the Practice application service composes database transactions and owner-scoped persistence, following the existing catalog service boundary. Routes use existing identity/cookie/CSRF dependencies. Each mutation locks its account before checking version, links, state, collisions and writes. PostgreSQL partial unique indexes enforce one unfinished session and one current goal per period. Routines/activities/goals/starts cascade on account deletion; optional links use SET NULL. JSON routine snapshots preserve intended activity order, not cached progress counters. Migration 0009 adds five tables and is additive over 0008. Downgrade is destructive and must only be used on disposable databases.

`/api/v1/practice`: GET current; GET/POST sessions; GET/PUT/DELETE sessions/{id}; POST sessions/{id}/{pause|resume|end|save}; GET/POST routines; GET/PUT/DELETE routines/{id}; POST routines/{id}/duplicate; GET goals; PUT goals/{daily|weekly}. Deletes take version query parameters; updates take version bodies; creation/duplication take UUID client_key. Commands carry version/confirm_long. Stale modifications return 409, unavailable own resources 404, invalid links/durations 422, deleted Start retry 410. All practice responses are no-store. OpenAPI is the complete contract.

No new prerequisites or third-party service. The normal launcher migrates local PostgreSQL and preserves existing data. Unit/integration/browser tests use isolated databases; never run their migration round trips on personal data. Optional external hosting uses the existing deployment plan; no provider decision changed. Content rights from Phase 12 and real-device tuner gates remain unchanged.
