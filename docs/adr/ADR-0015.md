# ADR-0015: Local metronome audio clock

Status: accepted, 2026-11-08.

Use browser-native oscillators scheduled ahead on AudioContext.currentTime, with a pure beat timeline separate from browser lifecycle and React controls. A 25 ms scheduler fills a 150 ms horizon; visual frames follow the audio clock. This bounds ordinary UI-stall sensitivity without a paid service or backend audio processing.

Start is an explicit user gesture. Stop/navigation closes the context and cancels timers; suspended contexts require a fresh Start. Missed beats after excessive delay are skipped. Continuous background/sleep playback is outside browser guarantees. BPM is 30–300 denominator-note clicks; 6/8 is six eighth-note clicks. Changing meter resets the measure; queued settings can retain old values for 150 ms. No persistence or database migration is needed.

Verification includes multi-minute pure timeline tests and native Chromium scheduling plus suspension/restart/navigation cleanup. These do not establish physical output latency or speaker quality.
