# ADR-0021: Shared content operations and private correction reports

Date: 2026-11-09. Status: accepted engineering decision for Phase 15.

Use one content-management application service over an explicit repository contract, composed with its SQL adapter in routes. Pure permission/revision policy is framework-independent. Boundary schemas validate documents using established song/rhythm/chord rules. Existing songs and patterns remain their authoritative records, so imports, withdrawals, private favorites and practice links retain identity. New reference documents support instruments/tunings/voicings without forcing unrelated private tables into a generic store. Legacy Phase 04 definitions remain seed inputs; tuner/shared-chord consumption moves to managed references.

Use draft/published/archived states with revision-checked saves, row locks, transactional audit and conflict-safe creation. Saving an existing item as draft withdraws it until republished, rather than introducing a separate parallel draft revision system. This is visible in the UI. No provider auto-publication. All new shared pattern writes require the same rich grant at publication; older original records retain their prior attestation until edited. Expiry is evaluated on reads and publication, and parent instrument availability gates tunings.

Reports have a non-null account owner FK with cascade deletion; only own reads or role-authorized moderation can access them. Moderator views omit reporter identity. Fixed dispositions avoid leaking private staff replies. Audit stores only actor/target/action/time, never report or content payloads. Actor FKs anonymize on deletion. Migration initializes metadata timestamps for existing rows but does not invent historic authorship. Long-term retention remains a pre-release policy decision.

Tradeoffs: JSON documents retain flexible per-component provenance, while kind/state/revision/FK/index constraints protect operational records. Tuning cardinality and instrument linkage are validated under row locks; reference deletion is archival only. Published-reference filtering occurs before pagination to avoid expiry hiding later pages. New instruments extend tuner definitions; profile/practice/chord families stay within the accepted baseline. Already delivered content cannot be recalled from clients. No new provider, paid infrastructure, framework or background worker.
