# ADR-0008: Backend composition and database lifecycle

Status: Accepted engineering decision
Date: 2026-11-08

## Context
Phase 03 needs database/error/logging infrastructure while business schema and identity belong to subsequent phases.

## Decision
FastAPI factory composes validated environment Settings, bounded sync SQLAlchemy/psycopg Database and lifespan disposal. Use explicit transaction contexts with automatic commit/rollback and connection release. Separate DB-independent liveness from connectivity readiness. Alembic is the only schema-upgrade mechanism, using optional direct URL and NullPool; initial revision deliberately creates no domain tables. Structured logs allowlist safe events/status/request IDs and suppress access query strings.

## Alternatives considered
Async database APIs add complexity before an observed need. Startup auto-create bypasses review and migrations. Logging raw exceptions/requests risks sensitive data leakage. Required database at startup prevents useful liveness when dependencies are unavailable.

## Consequences
Sync database operations run in sync endpoints/worker threads. Do not call them directly in async routes without offloading. Real PostgreSQL integration tests require disposable data; default tests explicitly skip only when no test URL is provided. Readiness checks connectivity, not schema revision. Business tables, repositories and permissions remain future phases.
