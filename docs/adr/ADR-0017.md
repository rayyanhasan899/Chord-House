# ADR-0017: Song catalog, staged publication and component rights

Accepted 2026-11-08. The owner explicitly confirmed sign-in for song discovery/learning and that no licensed popular-song lyrics/arrangement source is available yet. Favorites and collections remain private. No paid provider is introduced.

Keep catalog identity separate from permission to display music/text. Bundle 85 MusicBrainz core recording identities (30 en, 26 ur, 29 hi), plus six original lyric/chord practice songs (two per language). The popular entries have zero approved arrangements/texts. Original songs provide 18 instrument-specific chord exercises and eight text variants, including Roman Urdu/Hindi and two native-script variants. They are not substitutes presented as famous-song arrangements, and no melody/recording is supplied. Record all gaps in SONG-CONTENT-INVENTORY.json.

Use SongReference IDs for stable existing private workspace links. SongRecord stores a versioned validated catalog document, normalized identity/search text, language, publication state and component withdrawal keys. JSONB keeps provider-specific nested component/grant data extensible without cross-module ownership. Core identity and import key uniqueness, FK lifecycle and private favorite uniqueness are relational. Domain search/chord/publication functions are independent of transport/ORM. DTO validation checks bounded content, safe links, instrument/tuning compatibility and ordered chord placements.

Each metadata, arrangement and text component has its own origin, license, source, attribution, evidence, terms version, reviewer, expiry and display/cache/transpose permissions. Only reviewed, current, worldwide display/cache grants can be published initially; regional grants are rejected until a reliable territory policy exists. This is a conservative application policy, not automated legal verification. An authenticated content manager/admin stages immutable batches, reviews issues, then explicitly commits. Fingerprints/idempotency keys, source/identity deduplication, revision checks and transactions prevent accidental replacements or partial publication. Old batch payloads retain imported revision evidence. Metadata or individual text/arrangement withdrawal takes effect on subsequent API reads; no shared catalog response cache. Open detail views refetch on focus and every 30 seconds, and clear content if refresh fails. Already delivered content cannot be recalled from a user's memory/device.

Bundled seeding never overwrites a managed/withdrawn row. Research helpers fetch only metadata, respect provider rate limits and require a checked source selection before producing a publishable pack. Generic live provider access is not a dependency. No lyrics, charts, recordings or artwork are scraped. Full manager UI remains Phase 15; role-checked API and local import CLI are available now.

Transposition is a presentation transform of structured chord names, including slash bass, with explicit sharp/flat preference and unchanged storage. Only granted transposition is enabled. Diagrams must match instrument/tuning; unsupported shapes are labeled missing. Conservative capo advice is limited to standard guitar, known key, source capo zero and nonnegative transpose. Private saved songs reuse the existing owner-scoped Workspace and one optional collection per favorite. Duplicate historical favorites become notes during migration, preserving their text/links, before adding a unique owner/song favorite index.
