# ADR-0019: Persist active intervals and immutable routine snapshots

Status: Accepted implementation choice within Phase 13 authorization. Date: 2026-11-08.

Browser timers can be throttled, refreshed or retried. Persist UTC active intervals and running_since on the server, excluding pauses and flooring only the final summed microseconds. Capture profile timezone without deciding Phase 14 calendar policies. Countdown deadlines materialize at their precise active-time limit on a subsequent read. Ending and saving are separate; unsaved sessions never count as saved practice.

Lock the account as the transaction serialization boundary. Permit one unfinished session per account, use optimistic versions for edits, idempotent creation keys/save transitions, and reject overlapping saved active intervals. A minimal Start retry ledger survives physical session deletion to prevent resurrection; owner deletion cascades it. Validate 1 second–24 hours; ask explicit confirmation over four hours. Corrections replace intervals only when the user chooses to correct time.

Store ordered routine activities and copy an immutable snapshot into the session. Goal settings append effective-dated versions. Avoid mutable aggregate counters; Phase 14 will derive totals/goals/streaks from saved intervals and must handle edits/deletes. Reuse established local audio engines with explicit start and lifecycle cleanup. PRA-021 MAY selected. UNI-005 MAY deterministic suggestions not selected now; reconsider in Phase 16. No paid AI/provider needed.

Tradeoffs: reads can finalize elapsed countdown state; an open count-up includes idle time until paused/ended and requires human review. Minimal retry records persist until account deletion. Routine snapshots retain their original activity names until that session is deleted. No automatic activity assessment or progress charts are claimed.
