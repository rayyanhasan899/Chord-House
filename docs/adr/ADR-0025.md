# ADR-0025 — Stable local song assets behind a storage contract

Date: 12 November 2026. Status: accepted implementation decision for revised Phase 18.

The preferred player and folder library were uncommitted in the original codex/phase-15 checkout, while security/training/quality changes lived in later worktrees. Reconcile those files onto 7d157b3 in codex/phase-18-reconciled; preserve the dirty original and supplied media. Do not revert whole features based on branch numbering.

Choose relational active asset bindings separate from song metadata documents and file bytes. Keep operator-only explicit synchronization, stable identities/artist/favorites across replacement and mapped rename, checksum verification, bounded authenticated streaming and exact text. Missing sources never imply deletion. Local-only operation needs no provider. A request-scoped check cache and a single listing join avoid repeated asset hashing and database queries; rights decisions remain live per request.

Keep the existing player design; correct source-change cleanup, pending playback, duplicate seek labels and stale asynchronous errors. Bind generated capture fixtures to a stable navigator mediaDevices object across restart; this is synthetic evidence, not microphone certification. Increase audio scheduling lookahead from 150 to 300 ms to cover brief foreground stalls; preserve strict native-clock phase assertions and missed-beat recovery rather than changing accuracy targets.

Reject automatic identity guessing, imports on GET, public media URLs, fabricated copyright grants, MP3 database blobs, destructive migration and an authentication-provider rewrite. Media provenance remains unverified; external distribution is a Phase 19 gate. See ../architecture/SONG-ASSETS.md and the revised Phase 18 report for executed evidence and remaining gaps.
