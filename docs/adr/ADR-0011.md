# ADR-0011: Typed same-origin frontend and real browser verification

Status: Accepted engineering decision
Date: 2026-11-08

## Decision
Use a shared client session context backed by authenticated /me, public/protected route groups, same-origin API rewrites, generated OpenAPI types and openapi-fetch. Keep credentials in secure cookies and CSRF in memory. Use server authorization for every personal operation; static protected page HTML contains no private data. Adopt semantic native controls and shared CVA primitives for the initial design system.

## Alternatives and consequences
Cross-origin browser calls add CORS/cookie complexity; browser token storage was rejected. Fake API browser tests cannot prove session forwarding, so CI runs the real PostgreSQL/API journey. A small chord-display migration completes preferences. Production provider/mail choices and later learning tools remain their existing phase scope. Existing generated frontend type-file changes are not discarded or independently committed.
