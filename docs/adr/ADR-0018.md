# ADR-0018: Bound password work during catalog browser verification

Accepted 2026-11-08 as a small necessary prerequisite uncovered by Phase 12 integration checks.

One six-browser local run returned HTTP 500 during a pattern-test registration while the song journey passed. Approximately 450 MB of physical RAM was free at inspection. The prior safe logger did not retain exception type, so the original cause is not proven. [Argon2 documentation](https://argon2-cffi.readthedocs.io/en/stable/howto.html) describes the default 64 MB requirement and memory-constrained execution risks; the installed hasher also reports 65,536 KiB per job. Resource pressure is an inference, not a captured root-cause claim.

Bound hashing/verification to two concurrent jobs per API process with a three-second capacity wait. Keep existing Argon2 memory/time/parallelism parameters and encoded passwords unchanged. Capacity exhaustion/operational hashing errors return retryable 503 without internal details; actual mismatches return false. Regression testing runs eight real hash jobs and verifies the bound, parameters, successful verification and safe failure. Limit Playwright to two workers for this local machine. Do not hide failed checks with automatic retries.

Unexpected-error logs now allowlist exception class name alongside request ID/status, while still omitting exception message, trace, URL/query, request body, credentials and tokens. Safe-log tests cover the added field. This helps investigate a recurrence without printing secrets. Multiple deployed API processes multiply memory allowance; deployment sizing and broader abuse/load hardening remain their planned phases.
