# ADR-0009: Reference aggregates and private ownership proof

Status: Accepted engineering decision
Date: 2026-11-08

## Context
Phase 04 requires real domain/constraint evidence without prematurely implementing all feature workflows.

## Decision
Create instrument/tuning aggregates, minimal account identity anchor and owner-scoped private notes. Validate immutable domain objects independently of ORM; SQL adapters implement protocols. Register ORM metadata only in infrastructure composition. Review future entities and retention in DOMAIN-AND-DATA-MODEL.md; add feature tables with their slices. Reference seeds are explicit, transactionally idempotent and preserve edits/archive state.

## Alternatives considered
Creating every proposed table now would lock speculative feature design. Pure documentation would not prove ownership/FK/deletion correctness. Seed-on-startup would hide production changes. Full authentication/workspace endpoints are outside this phase.

## Consequences
Note persistence proves owner isolation but does not authenticate callers. Phase 05 must supply authenticated actors and expand the account schema. Domain validates cross-row tuning counts; SQL protects independent ranges, references and uniqueness. Cascade removes private notes on account deletion; shared reference data remains. No copyrighted song content added.
