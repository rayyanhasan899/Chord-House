# ADR-0022 — Integrated local learning and opt-in reminders

Status: accepted engineering decision, Phase 16, 2026-11-10. Owner reminder-delivery question remains unanswered; this decision does not represent an owner reply.

## Decision

The authenticated `/training` hub composes existing approved references, local audio, practice and private routines. The integration module owns private assessments, reminder preferences and atomic delivery claims. Pure pitch/question/timing functions stay independent of the UI; the pure reminder calendar rule stays independent of ORM/FastAPI. DTOs, application service and persistence models follow the existing modular-monolith composition.

Select UNI-005, UNI-010, UNI-021, UNI-022, UNI-023 and NTF-004 MAY capabilities. Transitions use 2–8 distinct chord labels, configurable intervals and optional local synthesized guides; random difficulty pools contain published compatible shapes. Challenge counts are explicitly self-reported. Ear questions cover notes, intervals and chord qualities at three selectable levels; feedback explains the answer. No microphone recognition or remote audio is added. Note finder uses actual octave/MIDI pitches, including re-entrant ukulele and alternate guitar tunings.

UNI-023 is selected as rights-cleared text-section selection, repeat/once visual pacing and optional generated line cues at adjustable tempo. Recording looping, melody playback and time stretching are unselected: no verified recording/playback rights are supplied. Popular-song metadata does not authorize text or audio. Existing component grants are rechecked at start and every 30 seconds; expiry/withdrawal stops practice. No new content or rights are acquired.

Suggestions use current instrument/skill, active daily goal (capped at 60 minutes; otherwise an explicitly unsaved 15-minute default), and the most recent compatible saved material. They remain reviewable and unsaved until an explicit Save. No paid AI. Assessment saves never change practice totals; the separate explicit saved-session workflow remains authoritative.

Reminders default disabled. Visible signed-in tabs check every 30 seconds and on focus/settings changes. The backend evaluates selected weekdays and HH:MM in the current profile IANA timezone, with a ten-minute delivery window. Nonexistent DST times are skipped; repeated times and revisited dates are deduplicated by account/local date. Settings use optimistic versions; account-row locks plus a unique delivery key serialize claims across tabs. A claim is at-most-once, not proof of display: crashes/network failures can lose a reminder. Closing/suspending all tabs prevents delivery. No push, email, service worker or cron promise is made.

Permission explanation precedes a separate user action. Only that action calls `Notification.requestPermission`; an enabled preference cannot trigger permission prompts. Denied/unsupported/error cases retain in-app reminders and all learning tools. Notification content is generic, with no private notes or promotion.

## Persistence and consequences

Reviewed migration `0012_integration` adds owner-cascaded assessments, versioned preferences and per-date delivery claims. Assessment owner/client UUID uniqueness and fingerprint make concurrent retries idempotent. Delete clears the JSON payload; a minimal key/hash/id/time tombstone prevents delayed retry resurrection until account deletion. Delivery dates similarly persist until account deletion. No raw audio or question answers are persisted; ear scores are page-local. Owner IDs come from the existing cookie session, writes retain CSRF/origin checks and responses are no-store. No public sharing route exists.

Audio has explicit start/stop and local ownership; tool changes, hide and navigation release it. Old asynchronous resume failures cannot stop a newer playback generation. A linked practice session can keep its server timer while training is open; returning to Practice still requires explicit End/Save for credit.

The dirty Phase 15 checkout is preserved. A separate worktree/branch and persistent preview database avoid applying a migration unknown to the retained checkout. Preview uses 127.0.0.2:3001, separate from the normal 127.0.0.1 host cookie, and new preview accounts. No personal data, credentials, roles or unfinished song-player changes are copied.

Reliable closed-browser reminders would require a separate product decision, delivery service and permission/reliability review. The present implementation satisfies the documented local contract; it must not be advertised as reliable background delivery.
