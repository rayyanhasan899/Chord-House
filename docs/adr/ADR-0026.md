# ADR-0026: Private portable song objects and a zero-dollar deployment gate

Date: 13 November 2026. Status: storage selected and provisioned; application hosting pending.

## Decision and actual configuration

Keep FastAPI, Next.js, PostgreSQL, server-managed cookie sessions and the local
adapter. Use private S3-compatible storage through the existing SongStorage port.
The application returns protected backend URLs; it never returns signed bucket
URLs. Internally generated short-lived signed requests used for provider testing
are test evidence, not a selected production delivery design.

The existing connected organization `org-steep-firefly-13302026` reports plan
`free`. Created project `broad-sky-05894064`, branch `br-sweet-band-az4blfcv`
(`production`), PostgreSQL 17, region `aws-ap-southeast-1`, and private bucket
`chord-house-songs`. Console: https://console.neon.tech/app/projects/broad-sky-05894064
Separate operator read/write and runtime read-only storage credentials were saved
outside source control. The owner database credential is for migrations only;
a non-owner database runtime role must be provisioned before API deployment.
The existing Devtreck project was not modified.

Compute is fixed at 0.25 CU. Configured project quotas: 288,000 compute seconds,
4,000,000,000 transfer bytes, 500,000,000 logical database bytes. Explicitly
setting the suspend interval was rejected with HTTP 412 on this account; retrying
without that unsupported setting succeeded. Do not describe that attempt as a
configured five-minute suspend interval: the returned endpoint setting is 0.
Free-plan sleep behavior is provider-enforced and must be checked in the console.
No plan upgrade, card, paid service, metered add-on or paid host was enabled.

## Measured workload and provider comparison

The retained source collection has 24 MP3s totaling **97,110,816 bytes**, 24 lyric
files totaling **59,109 bytes**, and a largest recording of **5,424,236 bytes**.
Four English, seven Urdu and thirteen Hindi folders remain on the owner's disk.
Permission to distribute these recordings/texts remains unverified.

| Candidate | Current published free allowance / limitation | Decision |
| --- | --- | --- |
| Neon PostgreSQL + private Neon Storage | 1 GB database/project; 100 CU-hours/project/month; 5 GB objects/project; 5 GB public transfer/project; six-hour restore history; supported Singapore region | Selected for this small library; cap and monitor usage |
| Neon PostgreSQL + R2 Standard | R2: 10 GB-month, 1 million Class A and 10 million Class B operations; no internet egress charge | Adapter-compatible alternative for higher traffic; no R2 billing enrollment performed |
| Supabase Free | 500 MB database, 1 GB files, 5 GB egress plus 5 GB cached egress; two projects; pauses after a week of inactivity | Alternative only; no auth/platform rewrite |
| Render Free backend / Node frontend | 750 shared instance-hours/month; sleeps after 15 minutes, roughly a minute to wake; ephemeral disk; free database expires after 30 days; SMTP ports 25/465/587 blocked | Evaluate only with a working zero-cost mail delivery path; no account or deployment configured |
| Vercel Hobby frontend | Next.js hosting candidate; streamed responses avoid the ordinary 4.5 MB response-body cap, but duration and transfer restrictions still apply | Do not assume MP3 proxy hosting is unlimited; no account configured |

At the configured four-billion-byte transfer budget, roughly 41 complete library
downloads or 988 average whole-track plays would consume the budget before
database traffic, verification downloads, seeks and retries. This is an estimate,
not a promised audience capacity. Open registration permits more than friends.
API media requests are throttled using the existing PostgreSQL rate limiter
(default 120 requests/account/window); the limiter's window is inherited from
identity. Operator imports default to 100 songs / 256 MiB per batch. These are
abuse controls, not a global monthly traffic guarantee.

Monitor project compute, public transfer, object volume, provider 429/503 errors
and API readiness. Review at 75% of allowances; stop imports or media traffic
before exhaustion. Stay on Free and accept suspension instead of upgrading.
Object lifecycle/versioning API configuration is not a substitute for backups:
Neon documents stored-but-unenforced lifecycle/versioning settings. Keep immutable
revision keys and matched independent backups.

## Hosting and release consequences

Prepared Dockerfiles and a private-network Compose topology with Caddy TLS and
same-origin `/api/v1` streaming. Only ports 80/443 are exposed. This needs an
existing free Docker host/DNS name and working mail credentials; the files do not
provision or buy either. Do not publish the owner's desktop or assume it is a
reliable public host. No live application URL exists from this phase.

Run controlled Alembic upgrades with the direct owner URL, then remove it from
the runtime environment. Use the pooled non-owner runtime URL, HTTPS, exact
trusted origins, secure cookies and read-only object credentials. Preserve local
startup without any cloud variables. Docker build context excludes source songs,
environment files, private evidence, dumps and local mail.
