# Main purpose of each phase

| Phase | Area | Main purpose |
| --- | --- | --- |
| 01 | Baseline and design | Reconcile requirements, architecture and acceptance criteria. |
| 02 | Repository foundation | Set up projects, developer tools and initial checks. |
| 03 | Backend foundation | Build API plumbing, configuration, errors and database connections. |
| 04 | Domain and database | Define domain rules, ownership and migrations. |
| 05 | Identity and accounts | Implement secure accounts, sessions and account recovery. |
| 06 | Frontend and design system | Build navigation, responsive screens and accessible forms. |
| 07 | Dashboard and workspace | Provide private tasks, notes, collections and preferences. |
| 08 | Instrument tuner | Detect microphone pitch and guide instrument tuning. |
| 09 | Chord library and audio | Browse, build and play chords; save private shapes. |
| 10 | Metronome | Provide adjustable, accurate practice beats. |
| 11 | Strumming patterns | Learn rhythms, hear playback and manage private patterns. |
| 12 | Song discovery and learning | Search English/Urdu/Hindi songs and use rights-cleared learning content. |
| 13 | Practice sessions and routines | Record practice, manage reusable routines and configure goals. |
| 14 | Progress and roadmap | Calculate totals, goal progress, streaks and learning roadmap. |
| 15 | Administration and content | Manage reviewed content and administration workflows. |
| 16 | Cross-feature completion | Connect features and complete remaining selected learning workflows. |
| 17 | Security, privacy and accessibility | Audit and harden safety, privacy and accessible use. |
| 18 | Quality and performance | Verify compatibility, reliability and performance. |
| 19 | Deployment | Prepare CI/CD and practical local/free-tier hosting. |
| 20 | Release and handoff | Audit completeness and deliver release documentation. |

This describes purpose, not completion status. See individual Phase-Reports for verified delivery and limitations.
